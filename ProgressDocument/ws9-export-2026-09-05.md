## 4. Architecture

```
                    SidePanel  (panel.pick.tabId, panel.lang)
                         │  injected: tab id + read-only gateway
                         ▼
            readDurableWorkflow          src/services/recording-workflow.ts
                         │  read-only · fails closed 4 ways
                         ▼
                 RecordedWorkflow        (the EXISTING model, unchanged)
                         │
                         ▼
            buildExportArtifact          src/recording/export.ts  — PURE
                         │  validateWorkflow (reused) → renderSpecFile (reused)
                         ▼
                  ExportArtifact         { language, filename, mimeType, content }
                         │
                         ├──▶ ClipboardPort ──▶ BrowserClipboardAdapter   IMPLEMENTED
                         │
                         └──▶ DownloadPort                                 BLOCKED (§11)
```

**Export decides nothing, and that is why it is safe to build.** Every locator in a recording was
decided **once**, at capture, against a live DOM, by the one resolver and the one probe, with slice
3's admission rule already refusing `.nth` winners, non-unique matches and low verdicts. Re-deciding
any of it here — resolving, ranking, re-verifying, normalising, or turning a chain back into a
selector to rediscover it — would be a second and weaker gate wearing the first one's clothes,
applied at the exact moment the code stops being ours and becomes a file someone runs.

**It refuses rather than fabricates.** Three refusals, each a fact about the input:

| Refusal                | Meaning                                                                                                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `no-workflow`          | Nothing stored, or what is stored cannot be trusted — decided by the **existing** `validateWorkflow`                                                                   |
| `empty-workflow`       | A recording that captured nothing. `renderSpecFile` returns `''` by its own convention; an empty **file** would look like a successful export, so the boundary says no |
| `unsupported-language` | Outside the seven. The type says impossible; the value crossed a storage boundary, so it is not                                                                        |

There is no fourth outcome in which something plausible is invented to fill a gap.

## 8. Security / Privacy

Proven, not asserted:

- **A recorded password never enters exported content.** A workflow whose password step was redacted
  exports as slice 4's `value withheld (password)` comment; the secret `hunter2` appears in **no**
  language's output, and a per-language loop asserts it.
- **A smuggled secret is refused.** A workflow whose redacted step illegally retained its value is
  rejected by `validateWorkflow`, and the refusal payload itself contains no secret.
- **No secret in the filename or the MIME.** Filenames are checked against the session id, captured
  values and the page URL, and contain none of them; they contain no digits at all.
- **No session id anywhere** in the export surface — not rendered, not in a name, not logged.
- **No logging at all**: `export.ts`, `recording-workflow.ts` and `ExportControl.tsx` contain no
  `console.` call.
- **No network, no telemetry, no new permission**: guarded against `fetch(`, `XMLHttpRequest`,
  `sendBeacon`, `WebSocket`, `analytics`, `telemetry`; the manifest is asserted unchanged.
- **No `eval`, no `new Function`, no `innerHTML`.**
- **`navigator.clipboard` appears only in `BrowserClipboardAdapter`** — asserted positively there and
  negatively across all three new files.
- **Playwright-only**: no Selenium, Cypress, WebdriverIO, Puppeteer or Robot Framework.

## 9. Architecture Guards

Added: no resolver/probe/ranker/verifier import from export or the reader · no second generator
(`generateLocatorCode`, `page.locator(`, `getBy*` forbidden in the export module) · no browser API,
storage, clock or randomness in the pure layer · no storage write from the export UI · workflow not
mutated · no lifecycle or session mutation · no second active-tab lookup · no logging · no secret in
a filename · `ClipboardPort` is the clipboard seam · the reader reads only `recording-workflow` ·
the action count appears nowhere.

**One existing guard was WIDENED, none weakened.** `preview-gate.test.ts` required the
`if (!RECORDING_ENABLED) return null;` early return for every component in `RecordingControl.tsx`.
Export exists only because recording does, so an export control that rendered while the flag is off
would advertise recording just as loudly — and, with `rt.start()` refusing, would be permanently
stuck in its empty state, the dead affordance DL-76 refused to ship. The identical rule now applies
to `ExportControl.tsx`, counted the same way. The change is commented in place.

## 13. The Download Blocker, Proven

| Evidence                                                         | Result                                                          |
| ---------------------------------------------------------------- | --------------------------------------------------------------- |
| `chrome.downloads` / `browser.downloads` anywhere in the product | **zero** — same as DL-76 found                                  |
| `URL.createObjectURL` / `new Blob` anywhere                      | **zero**                                                        |
| Manifest permissions                                             | `activeTab, storage, scripting, sidePanel` — **no `downloads`** |

`chrome.downloads` requires a **new permission**, which this gate forbids (§0 rule 23). The
permission-free alternative — an anchor plus an object URL — is a DOM trick inside the panel and
would materially expand the slice, which §11 says to stop and report rather than build.

So download was **not** built. What was built is the artifact it will consume, unchanged: tests
assert that `filename`, `mimeType` and `content` are exactly what the policy and the renderer
produce, so the later slice is a browser adapter and nothing more.
