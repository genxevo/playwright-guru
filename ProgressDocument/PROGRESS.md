## WS3 — Content-Script Runtime Split / LiveDomProbe 🟡 PARTIALLY COMPLETE (mirror-verified, uncommitted)

A fresh baseline was re-measured before any edit (789 tests/27 files, 276.09 kB, 2.67 kB headroom —
identical to the two prior same-day inspection passes) and the full locked architecture landed:
`entrypoints/content.ts` is now a thin WXT entrypoint; `src/runtime/probe.ts`'s `LiveDomProbe`
implements the WS0 `DomProbe` contract against the real DOM (the counterpart to WS1's
`FixtureDomProbe`) — a whole-document text index built exactly once per pick, memoized css/xpath/
role/label counts per expression per scope, reusing `resolveRole`/`computeAccessibleName`/
`matchesPlaywrightText` rather than re-deriving any rule; `src/runtime/capture.ts`'s `capturePick` is
the shipped hot path, preserving the unchanged `StoredPick` wire shape and the existing
`scoreCandidate`/`rankCandidates`/`buildLocatorChain` ranking policy — only the match-count SOURCE
moved, from the old ad-hoc O(n²) `===` counting to `resolveStep` + `LiveDomProbe`; `src/runtime/
fact-model.ts`'s `captureSnapshot` builds the full WS0 `PickSnapshot` (real, budget-checked,
independently tested) but is deliberately not imported by `content.ts`, so it costs zero shipped
bytes; `src/runtime/picker.ts` moved the highlight overlay into a closed shadow root with
rAF-throttled painting; `entrypoints/background.ts`'s two listeners merged into one typed router with
`isFromExtensionUI` sender validation and an `allFrames:true` executeScript retry target, matching the
content script's own new `allFrames:true`; the E4 CSS-escaping defect was fixed at all 8 confirmed
quoted-attribute call sites (a fresh grep found and fixed one site — old content.ts:529 — not
explicitly enumerated in the design blueprint's own table).

**Bundle: 280.74 kB, 1.98 kB (0.71%) OVER the 278.76 kB ceiling — disclosed, not silently shipped.**
Wiring `capture.ts` into the previously-dead `resolver.ts`/`rationale.ts`/`facts.ts`/`snapshot.ts`
domain modules initially crossed the ceiling by 8,427 B (the exact risk the design blueprint's §21/§28
flagged as unmeasured). Mitigation: physically splitting the shipped hot path (`capture.ts`) from the
full fact model (`fact-model.ts`, never imported by `content.ts`) lets Rollup's static-import-graph
tree-shaking guarantee zero shipped bytes for the latter, narrowing the overage to 1,980 B. A further
cut (dropping the picker's closed shadow root) was tried, measured to save only 182 B, and reverted as
insufficient and not worth the functionality loss. The remaining overage is partly an unfixable ~450 B
leak in the locked `rationale.ts` (`RATIONALE_CODES`/`CODE_SET`) and partly genuine new-functionality
cost. **Standalone IIFE probe build — DEFERRED, not implemented.** Re-confirmed this pass: DevTools no
longer uses `inspectedWindow.eval` at all (`handleDevtoolsPick` calls the same `capturePick` the
picker uses), so there is no live eval-context channel a standalone build would feed, and nothing in
the manifest, `wxt.config.ts`, or the codebase names a consumer — building it against a guessed
purpose would be exactly the "dead infrastructure to satisfy a checklist" the authorization
prohibited. Needs a project-owner decision naming the actual consumer. **New, disclosed limitation:**
with `allFrames:true`, `chrome.tabs.sendMessage` without a `frameId` delivers to every frame's content
script simultaneously and only the first response is used — a possible race for `VERIFY_SELECTOR`/
`PICK_DEVTOOLS_TARGET` where a frame with no match could win over the frame with the real answer; not
solved via a full frame-aware protocol redesign, judged out of WS3's scope.

Six new failure-first test files (`runtime-probe`, `runtime-dom-read`, `runtime-capture`,
`runtime-fact-model`, `runtime-picker`, `background-router`) plus four pre-existing files repointed
from string-matching the old `content.ts`/`background.ts` source to the new `runtime/*.ts` locations
with equivalent-strength assertions (`match-counts`, `honesty`, `devtools-architecture`, `visibility`)
— no assertion weakened, only relocated to where the guaranteed behaviour now lives.

## WS6.2 — Verification V2: locator parser, verifier, VerifyLocatorPanel 🟡 (DL-56, mirror-verified, uncommitted)

The genuine implementation milestone authorised as the next step after the WS5/WS6 owner-decision
gate: build the Playwright-subset locator-expression parser, the honest verification classifier, and
the `VerifyLocatorPanel` UI — not a framework rewrite, not a UI redesign, not a bundle-optimisation
sprint, not permission to reopen `PickSource`/Decision A or the leaf-first extraction.

**Inspection before design.** Reading `resolver.ts` in full first was decisive: `resolveChain` reads
only `chain.steps` and `chain.nth` — it never reads `chain.filter` or `chain.frameSelector`, even
though both are valid `LocatorChain` fields. That single finding drove the parser's most important
design decision: `.filter(...)` and `page.frameLocator(...)` are syntactically well-formed Playwright
calls, but parsing them into a chain the resolver would then silently ignore would be exactly the
"fabricated verification" failure mode this feature exists to prevent. They are rejected at the parse
boundary with an honest `UNSUPPORTED_METHOD`, not accepted and quietly under-resolved. `.nth(n)` **is**
supported — `resolveChain` does implement it correctly (narrows to a single match when
`visibleMatchCount > nth`), so echoing a user's own `.nth(0)` is not fabrication; the parser never
synthesises one that was not typed.

**Parser (`packages/locator-engine/src/parser.ts`, new).** A hand-rolled tokenizer + recursive-descent
reader — deliberately no parser-generator library (none was needed, and the authorisation's own
security rules rule out anything that gets there via dynamic code construction). Supports the seven
recommendable `getBy*` factory methods (role/text/label/placeholder/altText/title/testId), left-to-right
chaining, each step's options object (name/exact/checked/pressed/selected/expanded/disabled/level),
string and regex literal arguments, and a trailing `.nth(n)` — parsed directly into the existing
`LocatorChain`/`LocatorStep` AST (`types.ts`), no second locator representation introduced. A typed
`ParseErrorCode` (`EMPTY_EXPRESSION`/`UNEXPECTED_TOKEN`/`UNTERMINATED_STRING`/`UNTERMINATED_CALL`/
`MISSING_ARGUMENT`/`INVALID_ARGUMENT`/`UNSUPPORTED_METHOD`/`UNKNOWN_OPTION`) carries a caret `position`;
copy lives only in `ui/copy/verification.ts`, following the same domain-prose-exclusion discipline
`rationale.ts` established (R4 guard). A standing security-guard test (`parser.test.ts`) greps the
module source itself for `eval(`, `new Function`, and dynamic `import(` and asserts none are present —
not a one-time review claim.

**Verifier (`packages/locator-engine/src/verifier.ts`, new).** `verifyLocatorExpression(expression,
probe)` parses, then resolves through the SAME `resolveChain` the pick/recording paths already use
(`resolver.ts`'s own module doc names "Verify — user-supplied expressions" as one of exactly four
intended consumers — this is precisely the feature it was built for). `classifyVerification` is the
single place a match count becomes one of six honest states — `verified`/`not-found`/`ambiguous`/
`invalid`/`unsupported`/`unverifiable` — and never claims more confidence than the evidence supports: a
probe error is `unverifiable` (never silently read as a measured `not-found`), more than one visible
match is always `ambiguous` (never narrowed to a fabricated single answer), and a resolver-declined step
is `unsupported` (an honest "not implemented", distinct from "couldn't answer right now"). Proven
end-to-end against `FixtureDomProbe` (`test/verifier.test.ts`, 12 tests covering all six states plus
direct `classifyVerification` unit cases).

## WS6.2.1 — Verify-path dependency isolation gate: conclusive negative result 🟡 (DL-58, mirror-verified, uncommitted)

A single, tightly bounded engineering investigation: determine whether the WS6.2 verification path's

suspected root cause — `content.ts → verifier.ts → resolver.ts → resolveChain/resolveStep`, with the
